# bento-tools 3.0 design plan

This document is the planning artifact for [ckmah/bento-tools](https://github.com/ckmah/bento-tools). It uses [YeoLab/bento-tools](https://github.com/YeoLab/bento-tools) v2.1.4.post2 as historical reference only. Version 3.0 is a clean break, not a port.

## Executive summary

bento-tools 3.0 is a **subcellular** library on `SpatialData`. It measures **molecules** (transcripts and analogous point features) inside **segmented cells** and compartments, with **2D and 3D** support. **Persisted geometry is per-z polygons only** (see input contract); **3D analysis runs on ephemeral triangle meshes** lofted from those polygons, not on voxel label algebra. **RNAflux**, **shape_measure**, **point_measure**, and compartment composition are the core analysis surface. **RNAforest** is removed.

The public API **mirrors squidpy layout and conventions** (`bt.gr`-style module names where they fit, `key_added`, `copy`, results in `AnnData`/`SpatialData` slots documented per function). bento does **not** reimplement tissue-scale graph, co-occurrence, or spot plotting that **squidpy** already provides (see audit below). **GPU is optional**; **CPU is default**. Plotting uses **`spatialdata-plot`** and **`squidpy.pl`** for generic views; bento keeps only flux-specific renderers.

**Python 3.12+** is required. **No 2.x migration.** Algorithm choices for gene-pair interaction and RNAflux remain in [`docs/3.0-algorithms.md`](3.0-algorithms.md).

## Glossary

| Term | Meaning in bento 3.0 | Do not confuse with |
|------|----------------------|---------------------|
| **Molecule** | One detected transcript (or probe spot) with coordinates and a feature id (gene name). Stored in a `SpatialData` **points** element (e.g. `sdata.points["molecules"]`). | squidpy “points” in graphs, which are often **cell centroids** or spot centers. |
| **Transcript table** | The points element holding molecules; parameter name **`molecules_key`** (not `points_key` in new API). | Cell-by-gene matrix in `tables["table"]`. |
| **Cell id** | Primary instance key: **`cell_id`** (or documented alias in attrs). Every shape element (cell boundary, nucleus, …) is indexed by the **parent cell**. | Compartment-local ids without a cell parent. |
| **Instance** | One **cell** (table row) or one compartment geometry tied to a **cell_id**. | A single molecule. |
| **Centroid** | Tissue-scale cell center used by **`squidpy.gr.spatial_neighbors`** and similar (`spatialdata._core.centroids.get_centroids`). | Molecule coordinates. |
| **Region** | Named `SpatialData` element (`cell_boundaries`, `nucleus_labels`, …) referenced by `region` / `region_key`. | Image channel. |
| **Tidy features** | Long or wide tables of measurements with explicit `instance_id`, `region`, `feature_name`, `value` (cp_measure-style). | Wide unstructured `uns` blobs. |

### Instance and region IDs

**`cell_id`** is the single instance key for the `TableModel` and for every shape element (nucleus, cell membrane, custom compartments). Compartment polygons reference the same **`cell_id`** as the parent cell row. **`squidpy.gr`** builds graphs on **centroids** derived from shapes; bento **does not** reassign molecules or treat centroids as molecules.

## Input contract (locked)

Under this contract, data arrive **analysis-ready** from **`spatialdata-io`** (or from bento’s synthetic / platform fixture builders). **There is no `bt.pp.prep`.** bento does not rename columns, reassign molecules, resample geometry, or attach contract metadata blobs.

| # | Rule | Implication |
|---|------|-------------|
| 1 | **One 3D shape format:** **per-z polygons** in `sdata.shapes[region]` (required columns: **`cell_id`**, **`z`** in µm, geometry). | No **`Labels3D`** ingestion path; no marching cubes. **Outputs** from **`bt.geo`** and measures that write geometry → **per-z polygons** (same schema). |
| 2 | **One shared z grid per dataset:** the sorted set of **z** values is identical for all shape elements and molecule **z** coordinates (within tolerance). | Validated on demand; 2D-only data use a **single z** plane (degenerate grid). |
| 3 | **Physical units:** **microns** for x, y, z. **Anisotropic spacing is allowed**; resolution is **readable from SpatialData** (see below). | bento **does not** resample shapes or force isotropic voxels. RNAflux / optional GPI grids use **declared** spacing (see algorithms doc). |
| 4 | **One coordinate system:** all elements share the same spatial reference. | bento **never** reprojects, registers, or aligns slides. |
| 5 | **Cells as instance key:** every shape row carries **`cell_id`**. Set ops **preserve `cell_id`**; disconnected pieces after a boolean → **one multipart geometry** (MultiPolygon / equivalent) **under that `cell_id`**, not new ids. | Resolves instance-id and multi-body persistence policy for **`bt.geo`**. |
| 6 | **Molecules pre-assigned:** `sdata.points[molecules_key]` includes **`cell_id`** and **`feature_name`** (or `feature_key` in attrs). | Validated on demand; **no** point-in-polygon reassignment in 3.0. |

**Pipeline:**

```text
vendor raw  →  spatialdata_io.<platform>(path)  →  bt.tl.* / bt.geo / …
```

Optional: `bt.pp.validate(sdata, ...)` once up front for a full contract report.

**Platform conversion:** vendor parsing and contract-shaped **`SpatialData`** are **`spatialdata-io`**’s job (and **upstream PRs** when a reader still emits labels or wrong column names). **`scripts/build_platform_fixture.py`** (PR-15) may crop and **write Zarr** offline; it must output the same schema **`spatialdata_io`** would, not call bento prep.

### Validation (no prep)

| Mechanism | Behavior |
|-----------|----------|
| **`bt.pp.validate(sdata, *, molecules_key=..., region_key=..., report="text"\|"dict")`** | Optional **eager** pass: every contract rule, **all violations at once**, actionable messages (missing columns, z mismatch, missing resolution, invalid `cell_id` coverage). |
| **On-entry validation** | Every **`bt.tl.*`**, **`bt.geo`**, and relevant **`bt.pp.*`** helper validates **only the elements it touches**, cached per `(sdata id, element key, revision)` for the process lifetime. Users need not call **`validate`** first. |

### Resolution metadata (µm spacing)

Bento needs **`pixel_size_xy_um`** (in-plane µm per coordinate unit) and **`z_step_um`** for flux/GPI sampling grids and 2D slab thickness.

**Read order (spatialdata-native first):**

1. **XY — transformations:** For the reference shapes element (default `cell_boundaries`), use [`spatialdata.transformations.get_transformation`](https://spatialdata.scverse.org/en/stable/api/transformations.html) to the dataset’s **global** coordinate system. If the chain includes **`Scale`** on **x** / **y**, use those factors as µm per stored unit. If the chain is **`Identity`** and coordinates are already in µm (typical **`spatialdata_io.xenium`** / **merscope** outputs), treat **`pixel_size_xy_um = 1.0`**.
2. **Z — element attrs:** Read **`z_step_um`** from the reference shapes GeoDataFrame **`attrs`** (fixture builders and compliant readers set this when z is stored as physical positions). If absent, **infer** from the shared **`z`** column: median adjacent Δz when spacing is uniform (same check as rule 2); **`validate`** errors if inference is ambiguous.
3. **Missing / ambiguous:** **`validate`** (and on-entry checks) fail with a message pointing to either:
   - **`bt.pp.set_resolution(sdata, xy_um=..., z_um=..., region_key=...)`** — thin wrapper that sets **`attrs["pixel_size_xy_um"]`** and **`attrs["z_step_um"]`** on the reference shapes element (preferred when **`Identity`** + micron coordinates and z step is not inferable), or
   - plain SpatialData: update **`Scale`** on the element via **`set_transformation`** when the issue is pixel-space coordinates without a scale.

**Why not `uns["bento"]` for resolution?** Keeps spacing next to the **shapes** element and aligns with SpatialData’s **transform + attrs** model instead of a parallel bento-only config layer.

## API conventions (squidpy-aligned)

- **Modules:** `bt.pp`, `bt.tl`, `bt.im`, `bt.gr`, `bt.pl`, `bt.geo`, `bt.read`, `bt.datasets` (only modules with real surface area; no empty stubs).
- **Primary container:** `SpatialData` in function signatures; table access via `table_key: str = "table"` when an `AnnData` is needed.
- **`copy: bool = False`:** If `False`, mutate `sdata` in place; if `True`, return a modified copy (match `squidpy.gr.spatial_neighbors` pattern).
- **`key_added: str | None`:** When writing to the table, default names documented per function (e.g. `key_added="bento_shape_features"` → `adata.obs` columns prefixed or stored in `adata.uns[key_added]` per function contract).
- **Results placement:** Prefer **`table.obs`** for per-instance scalar/vector summaries, **`table.obsm`** for embeddings, **`table.uns[key_added]`** for nested results and metadata, **`sdata.points[molecules_key]`** only for molecule-level columns required for plotting (e.g. flux colors). Versioned bundle optional in `uns["bento"]` for cross-method provenance (PR-04).
- **Spatial keys:** `molecules_key`, `region_key` / `instance_key` align with SpatialData names; never `points_key` in new docs (alias deprecated if needed for one release).

### Compact public surface (3.0 target)

**`bt.pp`:** `validate`, `set_resolution` (only when resolution attrs / transforms are missing), `filter_molecules`, `spatial_dims`, `mesh_instances` (build or refresh ephemeral instance meshes)

**`bt.tl`:** `shape_measure`, `point_measure`, `list_shape_measurements`, `list_point_measurements`, `register_shape_measurement`, `register_point_measurement`, `flux`, `fluxmap`, `compartment_composition`, `compartment_enrichment`, `load_gene_sets`, `results` (accessor)

**`bt.geo`:** `union`, `intersection`, `difference`, `symmetric_difference` (2D **GeoDataFrame** regions); same four ops on **3D instance meshes** (in-memory); see geometry section

**`bt.im`:** Thin wrappers only if needed for molecule rasterization (else internal); **no** duplicate of `sq.im.segment`

**`bt.gr`:** **Reserved empty or docs-only** pointing to `sq.gr` for tissue graphs; optional future helpers that **call** squidpy on centroids without reimplementing

**`bt.pl`:** `flux`, `fluxmap`, `compartment_enrichment` (names TBD); doc examples use `spatialdata-plot` + `sq.pl`

**`bt.read` / `bt.datasets`:** Synthetic and tiny platform-style loaders into `SpatialData`

**Removed / not planned:** `analyze_shapes`, `analyze_points`, `bt.ut`, `lp*`, 2.x `coloc_quotient`, tissue-level duplicates of `sq.gr.*`, generic `bt.pl.points` / `density` / `shapes`

## shape_measure and point_measure (cp_measure model)

Reference: [cp_measure `featurizer`](https://github.com/afermg/cp_measure/blob/main/src/cp_measure/featurizer.py) returns **`(data, columns, rows)`** with shape `(n_objects, n_features)`, string column names, and row ids `(batch, object_name, label)`.

**bento adaptation:**

```python
# Config-style (optional): bt.tl.make_measurement_config(...)
features, columns, rows = bt.tl.shape_measure(
    sdata,
    region_key="cell_boundaries",
    measurements=["area", "perimeter", "eccentricity"],
    is_3d=False,
    copy=False,
    key_added="bento_shape",
)
# features: pd.DataFrame (tidy) OR ndarray + columns + rows
# If key_added set and copy=False: merge into table.obs / uns per contract
```

```python
features, columns, rows = bt.tl.point_measure(
    sdata,
    molecules_key="molecules",
    region_key="cell_boundaries",
    measurements=["inner_proximity", "molecule_dispersion"],
    groupby="feature_name",  # measure per gene group inside each instance
    is_3d=True,
    copy=False,
    key_added="bento_point",
)
```

- **`is_3d`:** Explicit flag like cp_measure (do not infer solely from array shape).
- **Composable primitives:** Low-level functions in `bento.measurements.shape` / `.point` (analogous to cp_measure `core.measureobjectsizeshape`); high-level API orchestrates per-**cell_id** geometry (2D polygon or 3D lofted mesh).
- **2D:** Shapely/geopandas regions at a single **z**; molecules filtered by **`cell_id`**.
- **3D:** Per-instance **triangle mesh** (see mesh layer); metrics via mesh (volume, surface area, sphericity, Feret-style extents where defined); molecules use **closest-point / inside** tests against mesh (`trimesh.proximity` or equivalent).
- **Output:** Default **tidy** `DataFrame` with columns `instance_id`, `region`, `measurement`, `value`, optional `group` (e.g. gene); optional wide pivot into `obs` via `key_added`.

**Not in bento:** CellProfiler-style **intensity** and **texture** on IF channels (use **cp_measure** or **sq.im.calculate_image_features**).

## Ephemeral 3D mesh layer

bento’s identity is **geometry** (polygons, solids), not **voxel image analysis** (skimage-style label arrays). For 3D, prefer **triangle meshes** held in memory for measurements, molecule assignment, and set operations—same product direction as [milume](https://github.com/ckmah/milume) cell lofting from **per-z polygons** (`cell-loft/loft.ts`, `CellPolygonStore` with LRU vertex budget ~2M).

### Library choice (implementation planning)

| Stack | Role | Pros | Cons |
|-------|------|------|------|
| **trimesh** + **manifold3d** (recommended default) | Mesh IO, proximity, volume/surface; **boolean union / intersection / difference** via Manifold backend | Pure Python ecosystem; matches “build mesh → measure / CSG → discard”; Manifold is fast and robust for watertight solids | Lofting from slices is **bento** code (milume-inspired); non-manifold inputs need repair |
| **pyvista** / **VTK** | Visualization and some boolean paths | Mature viz; familiar to microscopy viz stacks | Heavy optional dependency; boolean reliability and packaging weight for a core library |
| **Open3D** | Mesh processing | Good algorithms | Less aligned with SpatialData/shapely stack; another large dep |

**Decision for 3.0 design:** core dependency **`trimesh`**; **`manifold3d`** for 3D booleans in **`bt.geo`**; **`pyvista`** only under an optional `[viz]` extra if interactive debugging is needed. Do **not** make VTK a required install.

### Where meshes are built

| Source in `SpatialData` | Build strategy | Notes |
|-------------------------|----------------|-------|
| **Per-z polygons** (`shapes` with **`cell_id`** + **`z`**) | **Loft** matched slices (IoU / overlap matching between z planes; cap seams)—port concepts from milume `loft.ts` | **Only** persisted 3D input under the input contract |
| **Single-z 2D** | Treat as one-slice loft (slab thickness = declared **`z_step_um`**) | Degenerate shared z grid |

**`bt.pp.mesh_instances(sdata, region_key, *, cell_ids=None, force=False)`** warms the process cache for a subset of **`cell_id`** values before **`shape_measure`**, **`point_measure`**, or **`bt.geo`** 3D calls.

### Cache lifetime and memory

- **Key:** `(region_key, cell_id, geometry_revision)` where `geometry_revision` is a content hash of contributing per-z polygons.
- **Store:** In-process LRU capped by **vertex count** (default budget on the order of **~2×10⁶ vertices**, ~70–100 MB positions/indices—tunable; same spirit as milume `CACHE_VERTICES`).
- **Lifetime:** Per Python process / per `SpatialData` handle attachment; **not** written to Zarr. Cleared on `sdata` mutation of source geometry or explicit `bt.pp.mesh_instances(..., force=True)`.
- **Scale (order-of-magnitude):** A lofted cell mesh might be **10³–10⁴ vertices** (slice count × ring resolution). **10⁴ cells** therefore cannot stay resident at full fidelity; APIs batch by **instance list** or **spatial tile**, building only meshes for the current measurement/geo job. Peak memory is **O(cache budget + batch size × verts per cell)**, not **O(voxel volume)**.

### Persistence story (SpatialData out)

Meshes are **not** a first-class `SpatialData` element in 3.0.

| Operation | Persisted result |
|-----------|------------------|
| **`shape_measure` / `point_measure`** | Tidy tables → `table.obs` / `uns[key_added]` (unchanged) |
| **`bt.geo` 3D union / intersection / difference** | New or updated **`shapes`** element: **per-z polygons** sliced on the dataset **shared z grid**, same **`cell_id`** (multipart geometry when needed). No label raster persistence in 3.0. |
| **Internal** | Discard result mesh after persistence unless `copy=False` and caller holds returned `trimesh.Trimesh` objects in Python only (advanced) |

## bt.geo: 2D shapes and 3D mesh set operations

### What exists upstream

| Layer | 2D | 3D |
|-------|----|----|
| **shapely / geopandas** | `union`, `intersection`, `difference`, `symmetric_difference` via `gpd.overlay(..., how=)` and `shapely.ops.unary_union` | Polygons only (no volumetric solids in core Shapely) |
| **spatialdata** | Shape elements as GeoDataFrames; **`aggregate`** uses `gpd.overlay(..., intersection)` for shape–shape overlap | Stores **labels** and **shapes**; no mesh boolean API |
| **trimesh + manifold3d** | — | Watertight **mesh booleans**; proximity queries |
### Proposed `bt.geo` scope

**2D shapes** (`sdata.shapes[region]` at one **z**):

- `bt.geo.union`, `intersection`, `difference`, `symmetric_difference` — thin wrappers over **`geopandas.overlay`**; **`cell_id`** preserved per input contract
- `bt.geo.merge_instances` — dissolve touching polygons sharing a **`cell_id`** (cleanup)

**3D (mesh-backed):** Loft per **`cell_id`**, boolean on meshes, slice back to **per-z polygons** on the shared z grid. **Multi-part** results → **multipart rows** under the same **`cell_id`**.

- Operands: two **regions** (e.g. cell vs nucleus) for the same **`cell_id`** set, or explicit **`cell_id`** filters

**Out of scope:** Label-volume booleans; full-scene CSG on 10⁵ cells without batching; reprojection / resampling (violates input contract).

### Open questions (`bt.geo`)

1. Should results always be new **elements** in `sdata`, or optional **columns** on existing GeoDataFrames (2D only)?
2. Is **`bt.geo.overlay`** kept as alias for **`intersection`** (2.x compat name) or removed in clean break?

## Dimension-agnostic data model

**Container:** `SpatialData` only.

| Core shape | Role |
|------------|------|
| **MoleculeCloud** | `sdata.points[molecules_key]` with `feature_key` in attrs |
| **InstanceTable** | `TableModel` AnnData |
| **InstanceGeometry** | **Per-z polygons** per region (`cell_id`, `z`); 2D = single z plane |
| **MeshCache** (runtime) | LRU of per-instance `trimesh` solids for 3D measure/geo |
| **BentoResults** | Optional `uns["bento"]` schema version + method outputs |

Algorithm and performance sections unchanged in intent; see [`3.0-algorithms.md`](3.0-algorithms.md) for RNAflux and GPI. Hotspots: **flux**, **point_measure**, **mesh loft**.

## What changed from 2.x

Clean install. Notable API renames: `analyze_*` → **`shape_measure` / `point_measure`**; `points_key` → **`molecules_key`**; tissue graphs → **`squidpy.gr`**. No migration helpers.

## Risks

| Risk | Mitigation |
|------|------------|
| API drift vs squidpy | Pin `squidpy>=1.8`; re-audit on minor releases |
| Centroid vs molecule confusion | Glossary + lint parameter names in tests |
| Mesh loft correctness / seams | Golden tests vs milume-style fixtures; document IoU seam policy |
| 3D geo memory spikes | LRU + batch by instance; no full-volume label algebra |
| Fixture maintenance | One builder script; small Zarr |
