# bento-tools 3.0 algorithms discussion

This document is for **product and methods iteration**. It does not commit implementation. Parent plan: [`docs/3.0-design.md`](3.0-design.md).

**Terminology:** A **molecule** is one transcript (or spot) in `sdata.points[molecules_key]`. A **centroid** is a cell-level coordinate used by **`squidpy.gr`** (e.g. `sq.gr.spatial_neighbors`). Do not use “points” alone in API text. Measurements use **`bt.tl.shape_measure`** / **`bt.tl.point_measure`** (not `analyze_*`). Tests use **new** synthetic Zarr fixtures (`bento_synthetic_2d` / `_3d`), not 2.x `small_data.zarr`.

**3D geometry:** **Per-z polygons** only (input contract); **meshes** lofted on demand. Flux / optional GPI **sampling grids** use **declared µm spacing** (anisotropy allowed); bento does not resample shapes ([`docs/3.0-design.md`](3.0-design.md) input contract).

**Audience:** Clarence and contributors choosing what to build after 3.0 scaffolding lands.

## A. Subcellular gene-pair interaction (working name: GPI)

### A.1 Intent

Reframe legacy **colocation quotient (CLQ)** as a **ligand-receptor-style** deliverable at **within-cell** resolution.

- **Unit of analysis:** one **cell** (`cell_id`).
- **Output:** scores for **gene pairs** `(g1, g2)` with interpretable magnitude, direction, and uncertainty.
- **Aggregation across cohorts:** summarize to **cell-type × cell-type** or **group × group** tables (like CellPhoneDB / LIANA / CellChat report **sender–receiver** pairs), except groups are still **within** each cell’s own point cloud.

Legacy 2.x `coloc_quotient` computes, per cell, a **quotient of neighbor gene counts** vs marginals, then stores long-form CLQ tables and optional tensor CP (`colocation`). That API is **not** presumed for 3.0.

### A.2 Candidate statistics (per cell, per gene pair)

Each method below assumes **molecules** (transcripts) with coordinates **inside one instance**, a **metric radius** `r` in physical units (2D disk or 3D ball), and minimum count filters. This is unrelated to **`sq.gr.ripley`**, which models **cell centroids** at tissue scale.

| Method | Definition (sketch) | Interpretability | Null / calibration | Expression & size sensitivity | 2D / 3D | Cost (order) |
|--------|-------------------|------------------|--------------------|------------------------------|---------|----------------|
| **CLQ (2.x style)** | For each anchor transcript of `g1`, count neighbors with `g2` within `r`; aggregate to gene-level CLQ ratio vs cell marginals. | Familiar to bento 1–2.x users; ratio scale can be opaque. | Asymptotic CI in 2.x; fragile at low counts. | **High** on total counts; large cells have more pairs by construction unless normalized carefully. | Same formula with 3D ball neighbors; radius choice harder. | **O(cells × points × log points)** per cell NN rebuild in 2.x; GPU helps NN. |
| **Cross-K / cross-L (Ripley)** | `K_12(r)` vs `K_1(r) K_2(r)` from marked point process inside cell mask. | Standard spatial stats; `r` sweep shows scale. | Envelope from **within-cell CSR** (random labels keeping locations). | Normalized by intensity if CSR uses fixed locations; still needs enough points per gene. | Well-defined in 3D; literature for 3D marked processes. | **O(n log n)** per cell per radius with tree; multiple `r` multiply cost. |
| **Nearest-neighbor distance ratio** | Median `d(g2 | nearest g1)` vs median `d(g2 | any point)` or vs CSR. | Easy story (“g2 closer to g1 than chance”). | CSR label permutation at fixed coords. | Sensitive to **crowding** and gene density; less standard for “interaction”. | 3D NN distances trivial. | Moderate. |
| **Local enrichment z (LIANA-like)** | Observed count of `g2` within `r` of any `g1` vs mean under **within-cell label shuffle** (fixed positions). | **p-value / z-score** matches LR tool culture; pair list with significance. | **Permutation** (or analytic Poisson if homogeneous). | Shuffle fixes expression level per gene; still need `min_counts`. | 3D: same permutations. | **O(n_perm × pairs × work)**; prune to expressed pairs. |
| **Co-occurrence in voxels** (optional) | Rasterize to a **flux-style sampling grid** at **declared** Δx, Δy, Δz (may be anisotropic); count joint occupancy of `g1`,`g2` in a local window vs product of marginals. | Grid mirrors RNAflux sampling; stable at moderate res. | Block permutation within cell voxels. | Depends on **grid spacing**; large cells need more sites. | 3D: mesh-masked grid on shared dataset **z** steps; not label-volume morphology. | **O(sites + pairs)** per cell. |
| **Mutual information (MI)** | MI between binary or binned “g1 present in voxel” and “g2 present in neighborhood” across **sampling voxels** (optional GPI path). | Captures non-linear association; hard to explain `r`. | Permutation or Bayesian shrinkage. | Needs depth; biased for rare genes. | 3D sampling grid; not primary shape representation. | Moderate to high. |
| **Composition cosine (milume-style)** | Local gene **fraction vector** in window vs cell fraction; score pairs via **bilinear** term or full vector cosine (not strictly pairwise unless derived). | Matches **probe / similarity** intuition; less like classic LR tables. | Compare to cell vector (no perm) or bootstrap windows. | **Low** for pure scaling if using fractions (see measured note below). | Window ball in 3D. | Similar to flux neighbor step. |

### A.3 Measured prototype note (synthetic, not full CLQ)

A quick script (`/tmp/prototype_gene_pair_sensitivity.py`, not in repo) compared **marginal ratio** and a **crude permutation z** vs **L2-normalized composition deviation** when total counts scaled but **B|A biology** fixed.

| Scenario | B/A ratio | CLQ proxy (marginal ratio) | perm_z (crude) |
|----------|-----------|----------------------------|----------------|
| low_depth | 0.75 | 1.333 | 1.70 |
| mid_depth | 0.75 | 1.333 | 1.66 |
| high_depth | 0.75 | 1.333 | 1.71 |

**Measured:** marginal ratio is **invariant** to depth scaling when gene proportions stay fixed. **Measured:** L2 norm of normalized **local-vs-cell composition deviation** is **1.0** across depth scales 1–10 when compositions match.

**Inferred:** fraction-based scores separate **composition** from depth; raw count ratios and unnormalized CLQ need explicit **normalization or permutation** to avoid confounding by expression level.

**Naming:** prefer **`bt.tl.gpi`** (gene-pair interaction) or **`bt.tl.pair_scores`** over `coloc_quotient`. Tensor factorization (`colocation`) remains **out of scope** unless Clarence asks for a second phase.

### A.6 Recommendations to prototype

1. **Primary:** **Within-cell permutation z-score** for **local pair enrichment** at radius `r` (LIANA-style null, fixed transcript locations). Matches branding, gives **p-values**, extends to 3D balls, reuses the same neighbor index as RNAflux.
2. **Secondary:** **Cross-K at one or few radii** with CSR envelope for **scale interpretability** and figures (envelope plots per pair).

**Deprioritize for v1:** dense all-pairs CLQ without permutation (hard to sell vs LR culture), full tensor CP, MI-first API.

### A.7 Questions for Clarence (gene-pair)

1. **Branding:** GPI under `bt.tl.gpi`, or explicit `pair_test` / `subcell_lr` naming?
2. **Symmetry:** Score **ordered** pairs `(g1 → g2)` only, or symmetrize `min(p_ab, p_ba)`?
3. **Multiple testing:** FDR **per cell**, **per slide**, or **global** across all pairs?
4. **Radius:** Single global `r`, per-cell adaptive (e.g. fraction of cell radius), or report **sensitivity curve** over `r`?
5. **Minimum support:** Rules for `min_transcripts_per_gene` and `min_pairs` inside a cell?
6. **Cohort table:** Default groups from `obs` column (cell type) or require explicit `group_key`?
7. **Tensor / signatures:** Is **low-rank factorization** across cells still desired, or drop permanently?
8. **Legacy CLQ:** Any requirement to numerically match 2.x CLQ on a golden fixture, or clean break?

## B. RNAflux (subcellular composition similarity)

### B.1 What milume probe composition similarity does

Source: [milume](https://github.com/ckmah/milume) landmarks **probe / raster** path.

**Raster construction** (`frontend/src/widgets/landmarks/spatial-raster.js`):

1. Place a **square grid** on tissue XY with `bin_size` (default 8 µm when coordinates are µm).
2. Assign each **cell** to a bin by its XY position.
3. For each occupied bin, define a **soft window** (default radius `3 × bin_size`) and collect all cells whose centers fall in the window (KD-tree query).
4. Aggregate features per bin:
   - **`genes` basis:** mean of selected gene expression vectors over windowed cells.
   - **`composition` basis:** **category fraction histogram** over windowed cells (`compositionHistWindow`).
   - **`embedding` basis:** mean of `obsm` embedding dims.

**Similarity:** For a **query bin** (hover or pin), compute **cosine similarity** between **L2-normalized** bin feature vectors and every other bin (`milume/milume/static/landmarks.js`, `cosineScoresForQuery`). For point mode without raster, average features in a disk around the cursor then cosine to all cells.

**Important:** milume operates on **cells** in tissue space, not transcripts inside a cell. The transferable idea is **windowed composition vectors + cosine similarity**, not the literal cell-type histogram.

### B.2 What bento 2.x RNAflux does today

Source: `bento/tools/_flux.py` (YeoLab 2.1.4).

Per **cell instance**:

1. Build a **raster** of query sites inside the cell (future **`shape_measure`** raster primitive; 2.x used `analyze_shapes`).
2. For each site, count **molecule** neighbors in **radius or kNN** → sparse **gene count vector**.
3. **Local composition** = counts / sum(counts).
4. **Cell composition** = row of count table normalized.
5. **Flux vector** = `local_composition - cell_composition`, then **column-wise StandardScaler** (no mean).
6. Pool all raster points across cells → **TruncatedSVD** (≤10 components) → embedding dims `flux_embed_*`, colors via `vec2color`.

**fluxmap:** cluster flux embeddings (MiniSOM), polygonize domains.

**Gaps vs “rigorous statistical / embedding”:** no permutation null, no uncertainty, global SVD mixes cells, scaler and SVD order matter, 2D raster only, radius default tied to cell radius.

### B.3 Candidate 3.0 formulations

| ID | Formulation | Statistical meaning | Embedding | fluxmap domains | 2D / 3D |
|----|-------------|---------------------|-----------|-----------------|---------|
| **F1. Milume-adapted flux** | **Sampling grid** inside cell (mesh mask; spacing from **`flux_grid_spec`**) ; windowed mean of **local gene fraction**; L2-normalize; **cosine** to reference site or cell-average vector. | Similarity score in [-1,1]; not a p-value unless bootstrap added. | Optional PCA on fraction vectors or use cosine directly. | Cluster **similarity fields** or high-cosine regions. | 3D: ball windows on grid sites; boundary from lofted mesh. |
| **F2. CLR deviation flux (recommended core)** | Neighbor counts on molecule coordinates → **CLR** local vector; subtract CLR cell vector; **Hotelling or per-gene z** vs within-cell permutation. | Explicit **null** (shuffle gene labels at fixed coords). | PCA or UMAP on **significant** deviation vectors. | Domains from clustered **z-scores** or embedding. | 3D ball neighbors; optional **flux grid** for aggregation sites (declared spacing). |
| **F3. 2.x-compatible deviation + SVD** | Keep `local - cell` + scaler + SVD as **exploratory** view. | Weak inference; fast to port. | Same as 2.x. | Same MiniSOM path. | Port 2D raster; 3D uses grid + mesh mask. |
| **F4. Potential / density field** | Estimate gene-specific **kernel density** on sampling grid or molecule KDE; ratio to cell KDE. | Spatial scale via bandwidth. | Vector = stacked normalized densities. | Watershed on potential. | 3D KDE costly; prefer voxel counts on flux grid first. |

**Scale / radius:** Use **physical units (µm)**; default `r = α ×` (mean distance to **cell surface** from mesh, or 2D boundary) with **α** configurable. **Flux / GPI grids** use **`pixel_size_xy_um`** and **`z_step_um`** from the input contract (anisotropy OK); no shape resampling.

**CPU / GPU:** Neighbor count step dominates (same as GPI). **CPU:** KD-tree + Numba. **GPU:** cuML/cupy NN optional; SVD/PCA fine on CPU.

### B.4 Recommendations to prototype

**Primary: F2 (CLR deviation + within-cell permutation).**

- Aligns with milume **composition** thinking (fractions) and LR-style **nulls**.
- Produces **per-voxel or per-window gene-level z** and a low-dim embedding for visualization.
- Shares neighbor index with GPI.

**Secondary: F1 cosine field** for **interactive** “probe” UX (pin a location, color by similarity) without full permutation when exploring.

**Deprioritize:** global SVD across all cells without cell-wise normalization (2.x behavior) as the only export.

## C. Shared infrastructure (informs both A and B)

| Piece | Use |
|-------|-----|
| **Ephemeral instance mesh** (3D) | Inside tests, distances to surface, optional voxel masking for flux/GPI grids |
| **Flux sampling grid** per cell | Site placement for RNAflux F1/F3/F4 and optional GPI co-occurrence; spacing from contract metadata |
| **Molecule neighbor index** (2D/3D, radius or kNN on molecule coordinates) | GPI enrichment, flux local counts (F2 primary); distinct from **`sq.gr.spatial_neighbors`** on centroids |
| **Within-cell permutation** | Shuffle molecule `feature_key` labels, fixed coordinates |
| **Physical units** | All radii and grid steps in **µm**; shared coordinate system (no reprojection in bento) |
| **Pre-assigned `cell_id`** on molecules | No reassignment in bento; permutations shuffle gene labels only |
