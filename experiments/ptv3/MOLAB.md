# Running the PTv3 matrix on molab

`molab_gpu_run.py` is one self-contained marimo notebook (about 108 KB). It is generated by `ptv3_gpu/molab/build_molab_nb.py`
from `ptv3_gpu/molab/template.py` plus the scripts in `ptv3_gpu/` (in the bento3-proto workspace, not in this repo). To change it, edit those files and regenerate; do not edit the notebook itself.

> **New (Phase 2, first arm): `molab_lora_run.py`.** This one runs a pretrained Utonia-small PTv3 with LoRA adapters,
> molecules only, on the full Xenium IDC section (68.1M molecules). The notebook is minimal: it installs the
> `bento3_ptv3/` package, sets a `TrainConfig` and calls `train()`. Open it with
> https://molab.marimo.io/github/ckmah/bento-tools/blob/bento3-ptv3-molab/experiments/ptv3/molab_lora_run.py, pick the GPU
> (RTX Pro 6000), give it `HF_TOKEN` (molab Secrets, or the password box) and click Run all.
>
> Training is sized to ~9.5 h on whatever GPU it gets: the step count is measured over steps 50–250 and then fixed. A
> checkpoint goes to `hf.co/ckmah/bento3-ptv3-runs/lora/lora_ssl_s0/` every 15 min, and the run pauses itself at 11.25 h.
> After any cut-off, open a fresh session and Run all: it pulls the newest HF checkpoint and continues. See
> `bento3_ptv3/README.md` for details.

## Getting it into molab
- **Option A (recommended): from GitHub.** The notebook is on branch `bento3-ptv3-molab` of `ckmah/bento-tools` at
  `experiments/ptv3/molab_gpu_run.py`. Open
  `https://molab.marimo.io/github/ckmah/bento-tools/blob/bento3-ptv3-molab/experiments/ptv3/molab_gpu_run.py`.
  uv builds the environment from the PEP 723 header. This only works while the repo is public: molab downloads the file
  anonymously, and for the private repo it shows "Failed to Download File" (checked 2026-10-30). Until then use option B.
- **Option B: paste.** Open the scratch notebook (https://molab.marimo.io/notebooks/nb_d3bpcjKVJkV55nVggdX8b2), replace its code
  with the whole file, and let the package panel install the header's dependencies (torch 2.11.0 is already installed there).
  Then turn on the GPU and click **Run all**.

## What it needs and does
- **Inputs:** none from our box. The notebook downloads:
  - the 10x Xenium human breast 2-FOV bundle: `https://cf.10xgenomics.com/samples/xenium/2.0.0/Xenium_V1_human_Breast_2fov/Xenium_V1_human_Breast_2fov_outs.zip`
    (379,018,013 bytes, sha256 `cc1e987b…1779b`);
  - NuSPIRe from Hugging Face at revision `8e59fbb4…`;
  - PTv3 from Pointcept GitHub at commit `3229e9b7…` (sha256 checked per file).
  - Utonia's model code from Pointcept GitHub at commit `f832deb7…` (Apache-2.0, sha256 checked per file), and `utonia_small.pth`
    (148 MB, CC-BY-NC-4.0) from hf.co/Pointcept/Utonia at revision `9457f025…`, sha256 `3d7afb73…`, only when a `nuspU` arm is in the matrix.

  It rebuilds `mol.npz`; the sha256 matched our box's file in the box smoke test. It also rebuilds `dapi_feats.npz` and prints the
  same nucleus-AUROC sanity check as before.
- **Not hosted anywhere by us:** `mol.npz` (12.6 MB) and `dapi_feats.npz` (141 MB) are rebuilt instead of uploaded, so no data is duplicated.
- **Outputs** go under `bento3_work/full/` in the notebook's working directory:
  - `runs/<arm>_s<seed>/` holds `result.json`, `train_log.tsv`, `config.json`, `ckpt.pt` (every 1,000 steps), `model.pt`, `hier*.json`;
  - `runs/summary.md`, `runs/verdict.md`, `runs/run_molab.log`;
  - `figs/*.png`;
  - `bento3_results.zip`, the small files only, also offered as a download button.
- **Resume:** run all again. Finished steps are skipped and training resumes from `ckpt.pt`.
- **External store: Hugging Face Hub.** It is used only when `HF_TOKEN` is entered in the password box or set as an env var and the repo name is not
  the `YOUR_HF_USER/...` placeholder. The model repo defaults to `ckmah/bento3-ptv3-runs` (private, created on the first push).
  molab has no secrets feature, so paste a Hugging Face write token into the notebook's password box (the cell above config) before Run all. It stays in session memory only and is never saved in the notebook. The `HF_TOKEN` env var still works elsewhere.
  - `BENTO_HF_MODEL_REPO` (private model repo; created on first push if missing) receives `ckpt.pt` at every new checkpoint (1,000
    steps), plus every 30 min, after each run, and at the end. It also receives `model.pt`, `result.json`/`config.json`/`hier*.json`,
    `train_log.tsv`, logs, `summary.md`/`verdict.md`, and figures, under `full/` or `smoke/`. At start the notebook pulls the repo and
    keeps whichever copy of each run is further along, so a new session resumes from the newest checkpoint.
  - `BENTO_HF_DATA_REPO` (optional private dataset repo): the notebook loads `mol.npz`, `dapi_feats.npz`, `cell_boundaries.parquet`,
    and `nucleus_boundaries.parquet` from it. It checks `mol.npz` against the CPU runs' sha256. If anything fails it rebuilds from the
    public 10x files. Upload size: 12,565,710 + 141,418,109 + 700,126 + 657,067 bytes = 155.3 MB, or 154.0 MB for the two npz alone.
    This repo is optional: the rebuild takes roughly 1 min of downloads plus the NuSPIRe pass, so it is only a convenience.

## Monitoring (Trackio)
The notebook logs every run to [Trackio](https://github.com/gradio-app/trackio) (`trackio==0.44.0`), project `bento3-ptv3`
(`bento3-ptv3-smoke` for smoke runs), one run per arm and seed named `<arm>_s<seed>` and grouped by arm.
- **What is logged.** `train/loss_gene`, `train/loss_dapi`, `train/acc_masked`, `train/lr`, `train/s_per_step`, and `train/elapsed_min`
  come every 25 steps from `train_log.tsv`. `lr` is recomputed from train.py's schedule. `s_per_step` is averaged over about 100 steps,
  because `sec` is logged in whole seconds. After training come `eval/*` (held-out top-1, NLL, coverage, s/step, minutes), then
  `hier/*` and `hier_ctx/*` (ARI vs cells and vs k-means, nuclei/cells matched, chosen k, ToMATo, niche ARI). The arm's flags and
  settings are logged as the run config.
- **Abundance-aware eval.** Gene counts are heavy-tailed (15 genes with ≥ 10k training molecules make about half the held-out strip),
  so top-1 mostly scores abundant genes. `eval/*` also has `test_macro_recall` (mean per-gene recall; chance 1/280), top-1 within
  half-decade bins of training count (`test_top1_lt100`, `_100_300`, `_300_1k`, `_1k_3k`, `_3k_10k`, `_ge10k`), and two baselines on
  the same masked molecules (`base_majority_top1`, `base_prior_top1`). Per-gene counts go to `runs/<run>/per_gene.json`. Costs two
  bincounts per eval batch.
- **Audit scripts** (written next to train.py, not run by the notebook): `eval_detail.py RUN OUT.npz --variants real,zero,zero_flag,perm,shuf`
  re-evaluates a finished `model.pt` with the DAPI input kept, zeroed, permuted, or swapped for the tile-shuffled features and keeps every
  prediction; `abundance.py EVALDIR FIG.png` turns those into the per-bin table and figure (`knn_preds.py` adds the 20-NN baseline);
  `stem_weights.py RUN ...` compares how strongly each input group drives the first layer.
- **Images**, every 1,000 steps (`LOG_IMAGES` / `BENTO_LOG_IMAGES`, `BENTO_PREVIEW_EVERY`). Each one shows a fixed held-out window
  (x 1080–1180, y 325–425 µm, ≤ 20k molecules, the same molecules every time), using context predictions with each molecule's own gene
  masked (4 fixed 25% masks):
  1. true vs predicted gene for the top 12 genes, with the rest grey;
  2. a PCA of the context embedding, coloured nucleus / cytoplasm / unassigned;
  3. a top-20 confusion matrix.

  `train.py --preview-every` writes `preview.npz` under no_grad in eval mode, with the torch RNG saved and restored, so the training
  trajectory is unchanged. The notebook kernel draws the 600 px, dpi 80 Agg PNGs. Cost on the box CPU: about 1.2 s for the 4 forward
  passes plus about 0.55 s for the plots (which run in the kernel, not in train.py). On the GPU the forward passes should take a small
  fraction of that.
- **Never blocks training.** Trackio runs in the notebook kernel, not in train.py. A missing token or any Trackio error prints one
  warning and turns it off. Network calls have a timeout.
- **Where the dashboard lives.** It is public, at https://huggingface.co/spaces/ckmah/bento3-ptv3-trackio
  (direct link: https://ckmah-bento3-ptv3-trackio.static.hf.space). It is a free *static* Trackio Space, because Gradio Spaces
  need HF PRO (402 without it, whether public or private). Trackio logs locally in the session. `trackio.sync(..., sdk="static")`
  re-publishes the project to the Space and its public bucket `ckmah/bento3-ptv3-trackio-bucket`:
  - every `BENTO_TRACKIO_PUBLISH_MIN` (5) minutes, in a background thread;
  - when each run ends.

  Each publish took about 7 s from the box. No token or secret is stored in the Space; only the notebook's token is used to upload.
  Smoke runs do not publish. The Space shows one project, the last one published. As a backup and for resume, a consistent copy of the
  database and images also goes to the HF model repo with every checkpoint push (`full/trackio_hf/`). To view that copy offline:
  `hf download ckmah/bento3-ptv3-runs --include 'full/trackio_hf/*' --local-dir bento3_runs && TRACKIO_DIR=bento3_runs/full/trackio_hf uvx --from trackio==0.44.0 trackio show --project bento3-ptv3`.
- **Resume.** At start the notebook restores the Trackio database from the repo along with the checkpoints, and opens each run with
  `resume="allow"`, so a new session continues the same run. Rows below the run's last logged step are skipped. A run resumed from
  its 1,000-step checkpoint therefore replays steps without duplicating them, and steps stay global.

## Settings (environment variables)
| variable | default | meaning |
|---|---|---|
| `BENTO_SMOKE` | 0 | 1: nusp + nuspU, seed 0, 120 steps x 2 windows, to check the whole pipeline and read GPU s/step. Easier in molab: set `SMOKE_TOGGLE = True` at the top of the config cell |
| `BENTO_STEPS` | 15000 | training steps per run; the CPU runs used 3,000 |
| `BENTO_NWIN` | 4 | 100 µm windows per step; the CPU runs used 2 |
| `BENTO_ARMS` | `mol nusp nuspL0 shuf int nuspU nuspUs` | arms; `nuspU` = Utonia-small pretrained (weights hf.co/Pointcept/Utonia, CC-BY-NC-4.0, sha256-checked), `nuspUs` = same size from scratch |
| `BENTO_SEEDS` | `0` | seeds (later sessions: `1`, then `2`) |
| `BENTO_AMP` | none | `bf16` is faster, but check first that a short run tracks fp32 |
| `BENTO_SPCONV` | shim | `real` tries a spconv wheel that matches torch's CUDA, with a self-test and fallback |
| `BENTO_WORK` | `bento3_work` | output root |
| `HF_TOKEN` | (unset) | enables HF push/pull; without it nothing leaves the session |
| `BENTO_HF_MODEL_REPO` | `ckmah/bento3-ptv3-runs` | private model repo for checkpoints/results |
| `BENTO_HF_DATA_REPO` | `YOUR_HF_USER/bento3-xenium-breast-2fov` | optional private dataset repo with prebuilt data |
| `BENTO_SYNC_MIN` | 30 | minimum push interval while training, besides every checkpoint |
| `BENTO_TRACKIO` | 1 | 0 turns Trackio off (or `TRACKIO_TOGGLE` in the config cell) |
| `BENTO_TRACKIO_SPACE` | `ckmah/bento3-ptv3-trackio` | public static dashboard Space (empty in smoke mode); "" = no Space |
| `BENTO_TRACKIO_PUBLISH_MIN` | 5 | minutes between dashboard publishes (plus one at the end of each run) |
| `BENTO_TRACKIO_PROJECT` | `bento3-ptv3` | Trackio project (`bento3-ptv3-smoke` in smoke mode) |
| `BENTO_LOG_IMAGES` | 1 | dashboard images at checkpoint cadence |
| `BENTO_PREVIEW_EVERY` | 1000 | steps between images |

## Caveats
- molab stops a session after 12 h, and after 90 min idle. Keep the tab open while it runs.
- Files that are not uploaded through the file browser may not survive a shutdown. Set `HF_TOKEN` + `BENTO_HF_MODEL_REPO`, or download the results zip.
- molab notebooks are public but undiscoverable by default.
- GPU speed has not been measured. The first training log line prints s/step after 100 steps. Use that to size `BENTO_STEPS`.
